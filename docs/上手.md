# 上手指南

## 第一步:初始化

```bash
git clone <你的 fork/repo> && cd knowledge-compounder
go build -o kcp ./cmd/kcp     # 编译自研 agent(零外部依赖)
```

## 模型配置(任意 LLM 可跑)

```bash
export KCP_PROVIDER=openai-compatible   # 或 anthropic
export KCP_MODEL=deepseek-chat          # 或本地 ollama 模型
export KCP_API_KEY=sk-xxx              # 本地 ollama 可留空
```

## 第二步:喂第一个源

放一个 `.md` 进 `raw/`,然后编译:

```bash
./kcp status                       # 知识库状态 + 未编译 raw
./kcp compile raw/你的文件.md       # compiler agent 按 SCHEMA 编译
```

编译会:读全文 → 判断 origin → 写 source/concept/entity 页 → 标注矛盾 → 加 wikilinks。**人策展,agent 编译**——建概念页等策展决策点由你把关。

## 第三步:查询并 filed back

```bash
./kcp query "知识库里关于 X 有什么结论?"
```

好问题的答案会建议 filed back 成 `wiki/synthesis/` 页——**每次查询都是对知识库的投资**,这是复利的核心机制。

## 第四步:捕获观察(失败回灌)

```bash
./kcp observe -s strategy -T "发现:费率异常" -c "描述"
```

异常/失败/新模式先记下来,再决定是否编译回灌——这是复利闭环的入口。

## 第五步:把知识库喂给其他 agent

编辑 `.mcp.json`(参考 `context/.mcp.json.example`),指向 `context/wiki-mcp-server/server.py`。Claude Code / Codex 就能在写代码时 `search_wiki` 查你的私有知识库——踩坑记录、架构决策直接成为它们的上下文。

## 第六步:健康检查

```bash
./kcp lint       # 断链/孤儿
```

## 日常纪律(来自 SCHEMA)

- **捕获优先于完美**:看到异常先 `observe` 记下来,不用等完整分析
- **每周编译一次**:`observe` 列表 → 决定哪些值得编译 → `kcp compile` 逐个处理
- **失败必须记录**:亏损案例比盈利更有价值
- **不要重复捕获**:写前先查是否已有类似观察
