# 上手指南

## 第一步:装进你的 Claude Code

```bash
git clone <你的 fork/repo> && cd knowledge-compounder
# 确保有 Claude Code
claude        # 在项目目录打开 → 自动加载 .claude/agents 与 hooks
```

项目自带的 agents 会接管你的知识库工作:

- `coordinator`(默认 agent):理解意图、路由到 compiler/qa、串行维护 index 与 log
- `compiler`:把 raw 编译成 wiki 页(读 SCHEMA,按 origin 分流,交叉引用,标注矛盾)
- `qa`:lint 健康检查(断链/孤儿/矛盾/格式),自动修安全类问题
- `batch-compiler`:批量导入外部文件夹
- `converter`:PDF/EPUB/DOCX → 干净 md 进 raw/books/
- `observe`(skill):捕获异常/失败/新模式的观察

## 第二步:喂第一个源

放一个 `.md`(或 `.pdf`、`.epub`)进 `raw/`,然后对 coordinator 说:

> 编译 raw/ 里的新文件

compiler 会:读全文 → 判断 origin → 编译 source/concept/entity 页 → 检查矛盾 → 加 wikilinks → 返回变更清单。你在关键节点(建概念页?取舍?)把关——**人策展,agent 编译**。

## 第三步:查询并 filed back

```bash
claude    # 问:知识库里关于 X 有什么?
```

好问题的答案会建议 filed back 成 `wiki/synthesis/` 页——**每次查询都是对知识库的投资**,这是复利的核心机制。

## 第四步:把知识库喂给其他 agent

编辑 `.mcp.json`(参考 `context/.mcp.json.example`),指向 `context/wiki-mcp-server/server.py`。然后 Claude Code / Codex 就能在写代码时 `search_wiki` 查你的私有知识库——踩坑记录、架构决策、合约审计经验直接成为它们的上下文。

## 第五步:隐私导出

```bash
bash scripts/export-public.sh    # 生成 wiki-public/,剥离 PRIVATE 段与敏感字段
```

## 日常纪律(来自 SCHEMA)

- **捕获优先于完美**:看到异常先 `observe` 记下来,不用等完整分析
- **每周编译一次**:`obs-list` → 决定哪些值得编译 → coordinator 调度
- **失败必须记录**:亏损案例比盈利更有价值
- **不要重复捕获**:写前先查是否已有类似观察
