# 上手指南

## 第一步:初始化

```bash
git clone https://github.com/gcc2ge/knowledge-compounder.git && cd knowledge-compounder
go build -o kcp ./cmd/kcp     # 编译自研 agent(零外部依赖)
```

## 先零 LLM 验证:克隆即玩

构建后**不用配任何 key**,先跑一遍零 LLM 命令确认安装:

| 命令 | 需要 API key? | 说明 |
|---|---|---|
| `kcp status` | ❌ | 页面计数 + 未编译 raw |
| `kcp lint` | ❌ | 健康检查 |
| `kcp search "<查询>"` | ❌ | 混合检索诊断(词法 + 离线字符哈希向量),带 [A]/[B]/[C] 私有度徽标 |
| `kcp list` / `kcp skeleton` / `kcp index` / `kcp update` | ❌ | 确定性操作 |
| `kcp mcp` | ❌ | MCP server 的检索类工具(搜索/读页/相关/最近) |
| `kcp compile` / `kcp query` / `kcp eval` / `kcp mcp`(synthesize_for) | ✅ | LLM 综合/编译/打分 |

配 `KCP_EMBED_MODEL` 后检索升级为语义向量;留空则用本地字符 n-gram 哈希嵌入(离线、零依赖、确定性)。

先跑 `./kcp status` 和 `./kcp search "go channel 泄漏"` 看真实输出;需要走完整 `compile → query` 流时,再配下面的 key。

## 模型配置(任意 LLM 可跑)

```bash
export KCP_PROVIDER=openai-compatible   # 或 anthropic
export KCP_MODEL=deepseek-chat          # 或本地 ollama 模型
export KCP_API_KEY=sk-xxx              # 本地 ollama 可留空
export KCP_BASE_URL=...                # 见下方「BaseURL 必须带 /v1」
```

> ⚠ **BaseURL 必须带提供商 API 版本路径(通常 `/v1`)**。`kcp` 在 BaseURL 后直接拼 `/chat/completions`,漏掉 `/v1` 会打到站点首页/根路由,返回 HTML 而非 JSON,compile 会静默空转(已靠 exit code 拦为失败码)。

| 服务商 | BaseURL |
|---|---|
| DeepSeek | `https://api.deepseek.com/v1` |
| Ollama(本地) | `http://localhost:11434/v1` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| 其他(含中转) | 以该服务商文档为准,拼到 `/chat/completions` 能返回 JSON 即对 |

## 第二步:喂第一个源

放一个 `.md` 进 `raw/`(直接放 `.md`/`.txt`;PDF 先 `scripts/pdf2md.sh`,epub/docx 先转 md),然后编译:

```bash
./kcp status                       # 知识库状态 + 未编译 raw
./kcp compile raw/你的文件.md       # compiler agent 按 SCHEMA 编译
```

编译会:读全文 → 判断 origin → 写 source/concept/entity 页 → 标注矛盾 → 加 wikilinks。**人策展,agent 编译**——建概念页等策展决策点由你把关。

## 第三步:查询并 filed back

```bash
./kcp query "知识库里关于 X 有什么结论?"
```

好问题的答案会建议 filed back 成 `wiki/synthesis/` 页——**每次查询都是对知识库的投资**,这是复利的核心机制。

## 第四步:捕获观察(失败回灌)

```bash
./kcp observe -s strategy -T "发现:费率异常" -c "描述"
```

异常/失败/新模式先记下来,再决定是否编译回灌——这是复利闭环的入口。

## 第五步:把知识库喂给其他 agent

```bash
./kcp mcp   # 把 wiki 暴露成 MCP stdio server(纯 Go 零依赖)
```

编辑 `.mcp.json`(参考 `context/.mcp.json.example`),把这个 MCP server 接进 Claude Code / Codex——它们写代码时就能 `search_wiki` 查你的私有知识库:踩坑记录、架构决策直接成为它们的上下文。

## 第六步:健康检查

```bash
./kcp lint       # 断链/孤儿
```

## 日常纪律(来自 SCHEMA)

- **捕获优先于完美**:看到异常先 `observe` 记下来,不用等完整分析
- **每周编译一次**:`observe` 列表 → 决定哪些值得编译 → `kcp compile` 逐个处理
- **失败必须记录**:亏损案例比盈利更有价值
- **不要重复捕获**:写前先查是否已有类似观察
